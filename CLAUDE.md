# Проєкт: заяви з Word/PDF → чернетки в «Електронному суді»

Ти працюєш із користувачем, який **не програміст**. Код пишеш ти.
Спілкуйся українською мовою, простими словами, без жаргону. Кожну команду, яку
користувач має виконати сам, давай готовою до копіювання і пояснюй, що вона робить.
Перед початком спитай, яка в користувача система (Windows чи Mac), якщо ще не знаєш.

## Мета

Юристи вручну переносять позовні заяви в кабінет «Електронного суду»
(https://id.court.gov.ua). Інструмент має:

1. Брати заяви у форматі .docx або .pdf (в одному файлі може бути кілька заяв).
2. Витягати з них дані для форми Е-суду.
3. Показувати ці дані юристу на перевірку.
4. Створювати в кабінеті Е-суду **чернетку** заяви.

**Підписувати й подавати заяву буде людина.** Інструмент НІКОЛИ не натискає
«Підписати» чи «Надіслати» і не працює з ключем КЕП. Він зупиняється на статусі «Чернетка».

## Що вже відомо (перевірено)

- **Публічного API для створення заяв у Е-суді немає.** Тому працюємо через автоматизацію
  браузера: Python + Playwright зі **збереженим профілем браузера**. Юрист сам один раз
  входить у кабінет (КЕП / Дія.Підпис), далі програма працює в цій сесії.
  Обходити вхід не намагайся.
- **Текст позову треба вставляти у вбудований редактор Е-суду, а не прикріплювати PDF-файлом.**
  Відомо випадок, коли суд визнав позов, завантажений PDF-файлом, таким, що не відповідає
  вимогам. Додатки (докази) прикріплюються файлами.
- У Е-суді є статус «Чернетка». На цьому статусі заяву можна редагувати, переходячи між
  кроками її формування.
- Загальний шлях у кабінеті: «Заяви» → «Створити» → регіон / інстанція / суд → тип документа
  → учасники → текст у редакторі → додатки.
- **Точної структури форми (поля, кнопки, селектори) ти НЕ знаєш.** Не вигадуй селектори.
  Отримай їх із запису `playwright codegen`, який зробить сам користувач (див. крок 3 плану).

## План роботи

1. **Читач заяв** (можна робити й перевіряти одразу на `samples/zrazky.pdf`):
   - Прочитати .docx (python-docx) і .pdf (pdfplumber).
   - Розбити файл на окремі заяви. Кожна заява починається з рядка «До … суду».
   - Відкинути службовий текст між зразками (див. особливості нижче).
   - Витягти поля (див. «Що витягати»). Зберегти результат у JSON.
   - Згенерувати зрозумілу таблицю / HTML-сторінку для перевірки юристом.
   - Позначити поля, які не вдалося знайти, а не мовчки пропустити їх.
2. **Встановлення на комп'ютері користувача.** Підготуй покрокову інструкцію з установки
   Python, бібліотек і `playwright install chromium`.
3. **Запис одного проходу.** Користувач запускає
   `playwright codegen --save-storage=auth.json https://id.court.gov.ua`, входить у кабінет
   і вручну створює одну тестову чернетку, НЕ підписуючи її. Код із записувача він передає тобі.
   Пояснюй цей крок дуже детально: це головне джерело правди про форму.
4. **Заповнювач.** На основі запису напиши скрипт, який:
   - бере JSON із кроку 1;
   - відкриває браузер зі збереженим профілем;
   - якщо сесія закінчилася, чекає, поки юрист знову увійде;
   - заповнює форму, вставляє текст у редактор, прикріплює додатки;
   - зупиняється до підписання й лишає браузер відкритим для перевірки.
   Перед кожним створенням чернетки програма має питати підтвердження в консолі.
5. **Тестування** на 2–3 заявах. Користувач надсилає помилки й скріншоти, ти виправляєш.

## Що витягати із заяви

- **Суд:** назва й адреса.
- **Тип документа:** «позовна заява» або «заява про видачу судового наказу».
- **Предмет:** рядок після заголовка.
- **Учасники.** Для кожного:
  - роль: Позивач / Відповідач / Заявник (Стягувач) / Боржник;
  - тип: фізична чи юридична особа;
  - ПІБ або назва;
  - адреса;
  - РНОКПП (10 цифр) або код ЄДРПОУ (8 цифр);
  - телефон;
  - e-mail;
  - відомості про електронний кабінет: відсутній / невідомо / зареєстрований.
- **Ціна позову або ціна вимоги** (може бути відсутня).
- **Судовий збір** і позначка про звільнення від сплати з підставою.
- **Повний текст заяви** для вставки в редактор (без шапки, якщо форма Е-суду заповнює шапку
  сама; уточни це за записом codegen).
- **Список додатків:** номер і назва.
- **Дата** та ініціали підписанта.

Суми переводь у числа: «1 211,20 грн» → 1211.20.

## Особливості зразків (`samples/zrazky.pdf`, 7 сторінок, 3 заяви, дані вигадані)

1. **Позов про стягнення боргу за розпискою.** Шевченківський районний суд м. Києва.
   Є ціна позову 50 000,00 і судовий збір 1 211,20.
   Рядок підпису «____ / І.І. Іваненко /» опинився на окремій сторінці.
2. **Позов про розірвання шлюбу.** Личаківський районний суд м. Львова.
   **Ціни позову немає**, тільки судовий збір. Перед заявою стоїть службовий текст
   («Ось ще два зразки заяв…», «Зразок 1: …»), який НЕ є частиною заяви.
3. **Заява про видачу судового наказу** (зарплата). Франківський районний суд м. Львова.
   Ролі «Заявник (Стягувач)» і «Боржник». Боржник — **юридична особа** (ТОВ, код ЄДРПОУ).
   Замість «Ціна позову» тут «Ціна вимоги». Судовий збір 302,80 грн, але заявник
   **звільнений від сплати** (п. 1 ч. 1 ст. 5 ЗУ «Про судовий збір»).
   Назва суду в шапці розірвана переносом рядка.

Загальне: у PDF рядки переносяться посеред полів (адреса, «РНОКПП» на іншому рядку).
Склеюй шапку в один рядок перед розбором.

## Важливо

- Дані клієнтів — конфіденційні. Нічого не відправляй у сторонні сервіси без явної згоди
  користувача. За замовчуванням усе працює локально, правилами (regex).
  Варіант із Claude API для складніших заяв можна запропонувати окремо, з поясненням вартості.
- Скановані PDF (без текстового шару) потребують OCR. Визнач такий файл і попередь користувача.
- Інтерфейс Е-суду може змінюватися. Тримай селектори в одному місці, щоб їх легко було
  оновити новим записом codegen.
- Не порушуй правила користування Е-судом: жодного масового навантаження, лише по одній
  заяві з підтвердженням людини.

## Стан роботи

- **Крок 1 зроблено:** `chytach.py` (запуск: `python chytach.py <файл>`). Результат — у папці
  `rezultat/` (JSON для заповнювача + HTML для перевірки). Перевірено на `samples/zrazky.pdf`
  (усі 3 заяви), на Word-копії тих самих заяв і на PDF без тексту (видає попередження про OCR).
- Поле `tekst_dlia_redaktora` — текст від заголовка до дати, без шапки й підпису; шапка окремо
  в `shapka`. Що саме вставляти в редактор, уточнити за записом codegen (крок 3).
- Користувач на Mac, у Терміналі працювати не любить — давай файли `.command` для подвійного клацання.
  Код на GitHub: https://github.com/f2h8cgcfwg-source/esud (приватний). Користувач завантажує його
  кнопкою Download ZIP, тож папка на Mac зветься `esud-main`. Скрипти не залежать від назви папки.
- **Крок 2 (установка):** `vstanovyty.command` (python.org 3.13 → `.venv` → бібліотеки → Chromium →
  перевірка на зразках). Інструкція: `ВСТАНОВЛЕННЯ_MAC.md`.
- **Крок 3 (запис) підготовлено:** `zapys.command` спершу запускає `uviity.py` (вхід без запису,
  зберігає `auth.json` і `profil/`), потім `playwright codegen --load-storage=auth.json -o zapys/…`.
  Так пароль ключа КЕП не потрапляє в запис. Інструкція для користувача: `KROK3_ZAPYS.md`.
  Чекаємо від користувача файл `zapys/codegen_*.py` і знімки екрана.
- `auth.json`, `profil/`, `zapys/`, `zaiavy/` і результати розбору справжніх заяв — у `.gitignore`.
- Назва суду переводиться в називний відмінок (`sud.nazva`) для вибору зі списку Е-суду;
  оригінал — у `sud.nazva_v_zaiavi`.
